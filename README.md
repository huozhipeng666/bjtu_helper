# 交大小助手 · bjtu-helper

课表、DDL、成绩与常用校园服务，收进一个手机网页。

**在线使用：<http://bjtuhelper.bond>**

## 一、这个项目解决什么问题

一个学生每天要面对的信息，散落在教务系统、课程平台、校园邮箱、实验室预约站、成绩单系统里。每个系统独立登录、独立改版，真正需要回答的问题却只有三个：

1. **我这周有什么课，在哪上？**
2. **有什么东西快截止了，还剩几天？**
3. **这学期成绩怎么样？**

bjtu-helper 把这三件事收进同一套界面，并以「主动提醒」为核心设计目标 —— 不是等你想起来去查，而是在截止前推到你面前。

它不是课程表的又一个皮肤：课表只是底座，真正的产出是「**接下来要做什么**」。

## 二、主要特性

### 1. 课表：一眼看清这一周

- **周视图**按节次排布，课程卡片显示课程名、教室与教师，正在上的课高亮标记
- **周次过滤**：每周 / 单周 / 双周；支持**放假周**（学校整周不排课时显示「放假无课程」，而不是留一片空白）
- **多学期管理**：可切换学期，自定义开学日与总周数，周次与校历自动对齐
- **月视图**与课程拖拽排序
- **三种导入方式**：教务一键导入（统一身份认证）、拍照识别课表、CSV 模板
- **冲突检测**：同一天、节次重叠且周次集合有交集时标出冲突；只提示、不阻断，因为很多冲突是学生自己刻意安排的结果

### 2. DDL：在截止前主动提醒

- 按课程筛选、按截止时间排序，精确文案（已逾期 / 今天截止 / 还剩 N 天）
- **手机日历订阅（推荐方案）**：每个用户一条独立 ICS 订阅地址，内含 VALARM 闹钟（提前 1 天 + 提前 2 小时；全天任务提前一天晚 8 点），导入系统日历后由手机自己负责到点提醒 —— 不依赖网页一直开着
  - 支持 `webcal://` 一键订阅、下载 `.ics`、泄露后重新生成令牌
- **站内信**：成绩 / 作业 / 考试数据变动、共同计划到点提醒，都会在「我的 → 消息通知」留一条记录

### 3. 成绩与考试

- 成绩查询与**加权平均**：百分制与五级制（A / A- / B+ …）混合计算时，等级制按学校官方区间的代表分折算后计入，口径对齐学校成绩管理办法
- **成绩单下载**：中文 / 英文两版
- **考试安排**：考试时间、考场、座位号，支持导出
- 成绩、作业、考试数据落库后可**离线查看**；数据有变化时自动发站内信（`data_change`）

### 4. 校园应用：16 个，一次登录全部可用

按「学习 / 校园服务 / 工具」三类分组，支持搜索：

| 分组 | 应用 |
| --- | --- |
| 学习 | 课程平台作业、成绩查询、考试安排、课件下载、校历、CITEL、物理在线 |
| 校园服务 | 校园卡、校园网、校园邮箱、教室人数、教室占用、物理实验、演示实验 |
| 工具 | 成绩单下载、数据同步 |

设计要点：

- **教务类应用共享会话池**：任一应用登录一次（学号 + 统一身份认证密码，密码不落库），其余应用打开时自动复用，不活跃 2 小时后失效
- **数据同步**：一次登录同步课表 + 成绩 + 作业 + 考试四类数据
- **实验课一键加入课表**：「物理实验」「演示实验」的排课与预约，可按你自己设置的作息表换算成「第几周 周几 第几大节」写入课表与 DDL，重复点击不会产生重复条目
- **二维码与校园网**：校园卡、校园网为纯本地生成的二维码，不跳转任何第三方短链
- 标记 **beta** 的应用依赖解析学校系统页面结构，对方改版可能失效 —— 这是这类项目的固有成本，不是 bug

### 5. 账号体系与游客模式

- **本校学生**：学号 + 统一身份认证密码登录（走学校新 SSO，无图形验证码）
- **非本校用户**：邮箱注册 / 登录，注册带图形验证码防刷
- **游客模式**：未登录也能使用课表、DDL、考试、学期设置与反馈；只有「导入课表 / 拍照识别 / 教务导入考试」这三个需要访问学校门户的动作，才会**就地**弹出登录层，登录后未登录期间的数据自动保留（两边都有数据时由用户选择合并 / 覆盖）
- 游客账号 14 天不活跃自动回收（提交过反馈的跳过回收）
- **后台管理**：用户管理（新增 / 删除 / 重置密码 / 设为管理员）与反馈工单（分类、状态流转、回复）

### 6. 移动优先与多端

- **移动优先**：深色 / 浅色主题跟随系统或手动切换，底部四栏导航（本周 / 课表 / DDL / 我的），适配 iOS 安全区
- **PWA**：可添加到主屏幕，Service Worker 缓存应用外壳
- **Android 客户端**：WebView 外壳 + **三种尺寸桌面小组件**（2×2 紧凑 / 4×2 标准 / 4×3 完整可滚动），今日课程与最近 DDL 倒计时常驻桌面；倒计时由系统每 30 分钟本地重算，App 没打开天数也是准的。客户端不打包任何前端资源，网页更新即刻生效，无需重新发版

## 三、典型使用场景

**早上出门前。** 打开首页「本周」，今天几节课、在哪间教室、下一节课还有多久开始，一屏读完；桌面小组件连 App 都不用开。

**周一排计划。** 切到 DDL 视图，按截止时间过一遍本周任务，把「还剩 2 天」的那几项先做掉。剩下的交给系统日历 —— 到点手机会响，不用记得来查。

**期末出分。** 进「成绩查询」看分数与加权平均，需要提交材料时直接下载中文或英文成绩单。

**临时救急。** 上课要用课件、明天考试不知道哪个教室、校园卡余额不够 —— 从「应用」里直接找，不用在四五个系统之间反复登录。

## 四、技术栈

| 层 | 选型 |
| --- | --- |
| 前端 `web/` | React 18 + TypeScript + Vite；手写 CSS，无 UI 框架 |
| 后端 `server/` | Node.js + Express + 内置 `node:sqlite`（零原生依赖） |
| 数据 | SQLite 单文件，首次启动自动建表 |
| 客户端 `android-shell/` | 纯 Android 框架 WebView + AppWidget，不使用任何第三方库 |

几个刻意的取舍：

- 后端用 esbuild 打成**自包含单文件**，服务端不需要 `node_modules`，少一个环节就少一类故障
- 数据库用 Node 内置的 `node:sqlite`，避免了 `better-sqlite3` 之类的原生编译依赖
- SMTP 客户端是手写的，只为「发一封提醒邮件」不值得引入一个依赖树
- 前端不用组件库：全站样式集中在一个 CSS 文件里，改版时不用和框架的默认样式打架

## 六、本地开发

需要 **Node.js ≥ 22.5**（使用了内置的 `node:sqlite`）。

```bash
npm install     # 安装两个 workspace 的依赖
npm run dev     # 同时启动后端(3001)与前端(5173)
```

打开 <http://localhost:5173> 即可。生产构建与运行：

```bash
npm run build   # 前端产物 + 后端自包含单文件
npm start       # 单端口运行（API 与前端静态页一体）
```

> 拍照识别课表是**可选能力**，需要自备视觉模型服务；未配置时该入口不可用，其余功能不受影响。

## 七、安全与隐私

这个项目要处理学生最敏感的两类数据：**教务密码**和**课表/成绩**。对应的设计：

- **密码**用 `scrypt` 加盐哈希存储，登录失败按 IP 与按账号双维度限流
- **教务密码默认不落库**：仅在当次登录时用于向学校系统换取会话，用完即弃
- 需要长期保存的第三方平台凭据，用 **AES-256-GCM** 加密后入库
- 凭据传输走 **RSA-OAEP 信封**：即使 TLS 在某处被解开，也拿不到明文
- **会话令牌服务端只存 `sha256(token)`**，库被读走也无法直接冒用身份
- 明确**不收集**真实姓名、身份证号、手机号、定位、通讯录与相册

发现安全问题请走 GitHub 的**私密漏洞报告**（仓库 Security 页），不要开公开 issue —— 公开等于把漏洞告诉所有人。
